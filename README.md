# VLA Basis

An implementation-first tutorial for learning the basic structure of a
Vision-Language-Action (VLA) model.

The goal is not to reproduce a complete robot foundation model. The goal is
to build a small, inspectable system whose data flow can be followed from an
original image and a language instruction to a continuous action chunk.

## Project Goal

The first target is a simulated Franka action space:

```text
image + language prompt
	     |
	     v
      Qwen2.5-VL
	     |
	     v
   multimodal hidden states
	     |
	     v
   condition projector / bridge
	     |
	     v
   Diffusion Transformer or Flow Matching expert
	     |
	     v
	action chunk [H, 7]
```

The seven action dimensions represent a Franka 7DoF joint-space action. The
project does not require a physical robot, camera, or controller. At the
beginning, data can be synthetic and actions can be generated by simple rules.

## Learning Principles

This repository is organized around these practical questions:

1. What tensors are produced by a pretrained VLM?
2. How are visual-language features converted into an action condition?
3. How can a transformer generate a continuous action sequence?
4. What is the difference between diffusion sampling and flow-matching ODE integration?
5. Which parameters should be frozen, adapted with LoRA, or trained from scratch?

Every stage should have a small executable check before the next stage is
added. The intended workflow is to write the implementation personally and
use this README as the map of interfaces and experiments.

## Main Interfaces

The first implementation should preserve these shapes:

| Interface | Shape | Meaning |
| --- | --- | --- |
| Image | `[B, 3, H_img, W_img]` | Batched image input |
| VLM features | `[B, L, D_vlm]` | Multimodal hidden states |
| Action condition | `[B, L, D_model]` | Projected expert condition |
| Action chunk | `[B, H_action, 7]` | Franka continuous actions |

`B` is the batch size, `L` is the multimodal sequence length, and `H_action`
is the prediction horizon. Keep the sequence dimension explicit: predicting
`[B, 7]` can help with debugging, but the target VLA interface is an action
chunk `[B, H_action, 7]`.

## Learning Stages

### Stage 1: Load a Pretrained VLM

Use Qwen2.5-VL through Transformers and its processor. Verify:

```text
image + prompt -> processor -> model forward -> hidden states
```

At this stage, the VLM is frozen. `generate()` can confirm that the model
understands the image, but the VLA path should keep hidden states from
`forward(output_hidden_states=True)`.

### Stage 2: Build the Bridge

Project `D_vlm` to the action expert dimension `D_model`. Start with an MLP
and LayerNorm. Do not add cross-attention or adaptive normalization until the
simple bridge has been tested for shape correctness and gradient flow.

### Stage 3: Build the Action Experts

Implement two experts with the same action interface:

- **Diffusion Transformer:** predicts a denoising quantity for a noisy action sequence and uses a scheduler during inference.
- **Flow Matching expert:** predicts a velocity field along a path from noise to the target action and uses an ODE solver during inference.

The shared interface makes the comparison meaningful. Keep the training
objective, noise/path construction, scheduler, and sampler separate.

### Stage 4: Connect the End-to-End Model

The frozen-VLM baseline is:

```text
Qwen2.5-VL (frozen)
	+
trainable condition projector
	+
trainable action expert
```

Only after this version can overfit a tiny toy dataset should LoRA or partial
VLM fine-tuning be introduced.

## Toy Experiment

Start without robot data. Create simple images containing colored objects and
prompts such as `move toward the red object`. Map the target location to a
deterministic 7DoF action chunk. The mapping does not need to be physically
accurate; it only needs to test whether the model uses the image and prompt.

Useful checks are:

1. Change the image while keeping the prompt fixed.
2. Change the prompt while keeping the image fixed.
3. Shuffle action labels and verify that learning degrades.
4. Replace VLM features with zeros or random features and compare results.

## Installation

Create an environment suitable for the local machine, then install:

```bash
python -m pip install -r requirements.txt
```

The first Qwen2.5-VL run downloads model weights from Hugging Face and caches
them locally. A 3B checkpoint is the recommended starting point for a laptop.

## Verification Checklist

Before moving to the next module, verify the current one:

```text
[ ] The VLM and processor load successfully.
[ ] A single image and prompt complete a forward pass.
[ ] Hidden states have shape [B, L, D_vlm].
[ ] Hidden states contain no NaN or Inf values.
[ ] The bridge preserves the batch and sequence dimensions.
[ ] Both experts return [B, H_action, 7].
[ ] A tiny dataset can be overfit before scaling up.
```

## Scope and Non-Goals

This project currently does not provide:

- real robot control or safety guarantees;
- camera calibration, inverse kinematics, or trajectory execution;
- a claim that synthetic actions transfer to a real Franka robot;
- a reproduction of any particular published VLA system.

Those topics can be added after the basic tensor flow, training objectives,
and sampling procedures are understood.
